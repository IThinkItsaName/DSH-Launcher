## 0. 先看结论（建议）

推荐先做**形态 A（仅主窗口背景图 + 可调不透明度 + 一键恢复默认）**，并把"卡片底不透明度下限"作为硬约束写进规范；
形态 B（所有窗口）与形态 C（与 dsh 主题联动）**暂不建议**，理由见 §3。若你同意 A，按 §5 的 4 个变更集拆开做，每步独立验证。

## 1. 现状（事实）

| 事实 | 出处 |
|---|---|
| 主窗口是**透明窗**（`AllowsTransparency` + `WindowStyle=None`），因此其内部文字走**灰度抗锯齿**；其余窗口是标准窗口、ClearType 正常 | `docs/UI-DESIGN.md`「窗口」小节（变更集 139 实测） |
| 规范明确规定**最小字号 11px**，且**禁止**"半透明（<40%）底 + 11px 小字"；卡片阴影必须独立分层 | `docs/UI-DESIGN.md` §三 卡片/阴影 |
| 全部视觉走 `App.xaml` 令牌（颜色/圆角/间距），且 harness 有门禁：`App.xaml` 之外不得出现颜色字面量 | 变更集 127/132 门禁 |
| 已有的相关能力：dsh-market 主题（`DshMarketThemeService`，通过 loopback 接口读/应用 dsh 侧主题；应用前自动建 Plugin 范围快照） | `CURRENT_DESIGN.md`（插件市场段） |
| 启动器自身设置文件：Launcher 级 `launcher-settings.json`；每实例 `version-settings.json` | `CURRENT_DESIGN.md`（版本设置与整合包段） |
| 分享物 `.dshpack` 会脱敏并与"设计配置"打包；**本机路径**类设置（如手动绑定路径）不进包 | `CURRENT_DESIGN.md`（同上） |

**由此产生的三条硬约束**（任何方案都必须满足）：

1. 主窗口小字本来就在灰度抗锯齿下，背景图会进一步降低对比度 ⇒ 卡片背景**不能**变得更透；
2. 图片路径是**本机设置**，不应进 `.dshpack`（与"手动绑定打开方式"同类处理）；
3. 新增颜色/透明度必须走令牌，不允许在各页写局部透明度（否则门禁与后续主题化都会更难）。

## 2. 三种可选形态

### 形态 A（最小）：仅主窗口背景图
- 设置项：`launcher-settings.json` 新增
  `Wallpaper = { enabled, imagePath, opacity(0.2–0.8), fit: Fill|Uniform|Tile }`（旧文件缺字段→默认关闭）。
- 图片存放：内置图放 `Assets/`（打包进 exe，体积敏感，建议每张 ≤300 KB）；
  用户图片**不复制**，只记绝对路径（与"本机绑定路径"一致口径）；也可选择复制到数据根 `wallpaper/`（便于整目录拷走，见形态 A+）。
- 渲染：`MainWindow` 根 `AppRootBorder` 下加一层 `Image`（`Stretch` 按 fit），之上叠一层半透明遮罩
  （建议白色或深色遮罩，让卡片区对比度可控）；卡片保持**不透明**（`CardBrush` 不变）。
- 恢复默认：设置项里"清除壁纸"回到纯渐变底。
- 风险：低。**不改任何现有颜色令牌**；卡片仍不透明，11px 小字可读性不受影响。

### 形态 A+（便携增强，可选）
- 把用户图片复制到 `<数据根>\wallpaper\`（≤8 MB/张、格式白名单 jpg/png/webp），路径用相对路径记录 ⇒ 整个文件夹拷走仍生效。
- 代价：多份用户数据副本，需要在「存储与清理」里登记一类可清理项（只清 Launcher 自有副本）。

### 形态 B（全局）：所有窗口/内嵌页都有背景
- 需要给 12 个窗口 + 8 个内嵌页统一背景宿主；卡片、列表、表头全部要重新评估对比度；
  透明窗范围不能扩大（ClearType 降级范围会变大）。
- 风险：高（可读性、性能、每页截图回归）。收益：观感统一。

### 形态 C（与 dsh 主题联动）
- 启动器读 dsh-market 的主题名/图片，或反过来把启动器壁纸推给 dsh。
- 风险：跨产品耦合 + 依赖 dsh-market loopback 接口的可用性；且"应用主题前自动快照"这类既有逻辑要一起考虑。
- 收益：两侧观感一致。

## 3. 为什么建议先做 A（理由）

1. **成本/收益比**：A 只碰 1 个窗口 + 1 个设置项 + 1 个令牌（遮罩），一次性可验证；
   B 要逐页做对比度回归（本仓已有 27 张截图基线的工作量）。
2. **不破坏既有契约**：A 不动 `CardBrush`，因此"禁止 <40% 底 + 11px 小字"这条规范不需要放宽；
   B/C 都可能迫使放宽它。
3. **与现有功能边界一致**：壁纸是"外观偏好"，与实例/运行数据无关，放 `launcher-settings.json`（Launcher 级）即可，
   不需要进 `.dshpack`，也不需要按实例区分（避免又多一处"两处入口"）。

## 4. 需要你拍板的问题（5 条）

| # | 问题 | 备选 | 推荐 |
|---|---|---|---|
| Q1 | 范围 | 仅主窗口 / 主窗口 + 独立窗口 / 全部（含内嵌页） | **仅主窗口** |
| Q2 | 图片来源 | 内置几张 / 只支持本地文件 / 本地 + 网络 URL | **内置 2–3 张 + 本地文件**（不支持 URL：避免把网络依赖引入启动路径） |
| Q3 | 是否允许半透明卡片 | 卡片保持不透明 / 允许 85%–100% / 允许更低 | **卡片保持不透明**（遮罩负责观感） |
| Q4 | 图片是否复制进数据根 | 只记路径 / 复制进 `<数据根>\wallpaper\` | 视你是否要"整目录拷走仍生效"→ 若要，选复制（A+） |
| Q5 | 与 dsh 主题的关系 | 互不干扰 / 联动 | **互不干扰**（本轮只做启动器自己的背景） |

## 6. 明确不做（本轮）

- 不做全局背景（形态 B）与 dsh 主题联动（形态 C）——除非 Q1/Q5 改成要。
- 不做"壁纸自动换/轮播"、"从网络拉图"、"壁纸随实例切换"：都不在 UI-TODO 的诉求里，且会引入额外状态。
- 不为壁纸新建独立文件格式（`.dshwall` 之类）：现有设置字段足够；将来若要分享再单独评估
  （那时才需要处理"图片进包 + 体积上限 + 版权"三件事）。
